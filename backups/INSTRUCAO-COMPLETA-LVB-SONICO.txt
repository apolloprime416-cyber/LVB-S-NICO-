2. ARQUITETURA / TECNOLOGIAS
------------------------------------------------------------
Monorepo pnpm com workspaces:

- artifacts/painel ......... frontend React 18 + Vite +
  TypeScript + Tailwind + shadcn/ui (Radix), wouter para
  rotas, TanStack Query para dados.
- artifacts/api-server ..... backend Express 5 + TypeScript,

  connect-pg-simple (tabela user_sessions no Postgres).
- lib/db ................... schema Drizzle compartilhado.
- lib/api-spec ............. contrato OpenAPI (openapi.yaml)

- lib/api-zod .............. schemas zod (validar respostas)

LVB-XXXX-XXXX-XXXX (hexadecimal maiusculo).

O frontend e servido em "/" e a API em "/api" no mesmo
dominio (evita CORS). O servidor le a porta da variavel de
ambiente PORT.

3. BANCO DE DADOS (TABELAS)
------------------------------------------------------------
users:
- id (uuid), name, email (unico), passwordHash,
  role ('admin' | 'client'), status ('pending'|'approved'),
  createdAt, updatedAt.

license_keys:
- id (uuid), code (unico, LVB-XXXX-XXXX-XXXX),
  plan ('trial'|'daily'|'weekly'|'monthly'|'lifetime'),
  status ('inactive'|'active'|'expired'|'revoked'),
  userId, userEmail, deviceFingerprint (HWID),
  customerName, customerEmail (cliente final, p/ revenda),
  activatedAt, expiresAt, createdAt, updatedAt.

payments:
- id (uuid), userId, plan, amountCents, provider
  ('pushinpay'), providerPaymentId, status
  ('pending'|'paid'|'expired'|'failed'), qrCode (copia e
  cola), qrCodeBase64 (imagem), keyId (key entregue),
  createdAt, updatedAt.

extension_files:
- guarda o zip da extensao enviado pelo admin (bytea ou
  storage), filename, size, updatedAt.

user_sessions: tabela do connect-pg-simple (criar
manualmente: sid, sess json, expire + indice).

REGRA DE OURO DAS KEYS: a contagem de tempo SO comeca na
ATIVACAO (nao na compra). Duracoes: trial 15 minutos, daily
24h, weekly 7 dias, monthly 30 dias, lifetime sem expiracao.
Status "expirada" e calculado dinamicamente: se status =
active e expiresAt <= agora, responder "expired".

4. AUTENTICACAO
------------------------------------------------------------
- Cadastro de cliente: nome, email, senha (min 8).
- Login em 2 etapas para ADMIN: email + senha e depois um
  codigo fixo de seguranca (segunda etapa). Cliente comum

5. ROTAS DA API (prefixo /api)
------------------------------------------------------------
Publicas:
- POST /auth/register, POST /auth/login,
  POST /auth/verify-code (2a etapa), POST /auth/logout,
  GET /auth/me.
- POST /public/validate  { code, fingerprint } -> usada pela
  EXTENSAO. Logica:
  * key inexistente -> { valid:false, reason:"not_found" }
  * revogada -> reason:"revoked"
  * expirada -> reason:"expired" (e marca no banco)
  * inativa -> ATIVA agora (grava activatedAt, expiresAt,
    deviceFingerprint = fingerprint recebido)
  * ativa com fingerprint diferente ->
    reason:"device_mismatch" (1 dispositivo por key)
  * ativa e mesmo fingerprint -> { valid:true, plan,
    expiresAt }

Cliente (/me):
- GET /me/keys (minhas keys)
- POST /me/keys/activate { code } (reivindicar/ativar)
- POST /me/keys/:id/reset-device (liberar HWID p/ trocar
  de computador)
- PATCH /me/keys/:id/customer { customerName, customerEmail }
  (etiqueta de cliente final na key — validar formato de
  email, max 120 chars, aceitar null para limpar)
- POST /me/trial { customerName?, customerEmail? } — gera
  key de teste de 15 min. REGRA: so pode se o usuario tiver
  ao menos 1 key paga nao revogada.
- GET /me/extension (status do download: liberado se tiver
  key paga) e GET /me/extension/download (zip).
- GET /me/payments (meus pagamentos) e
  POST /me/payments/:id/check (conferir pagamento manualmente).
- POST /payments/create { plan } -> cria cobranca PIX na
  PushinPay, salva payment pending, retorna qrCode +
  qrCodeBase64.

Admin (/admin):
- GET /admin/stats (contadores do dashboard)
- GET /admin/users (+ aprovar, mudar status, deletar)
- GET /admin/keys (filtros por plano/status)
- POST /admin/keys/generate { plan, quantity (1..500),
  userEmail? } -> gera keys em lote
- POST /admin/keys/:id/revoke, /reset-device, DELETE /:id
- PUT /admin/extension (upload do zip da extensao)
- GET /admin/payments (todos os pagamentos)

PAGAMENTO PushinPay (PIX):
- Criar: POST https://api.pushinpay.com.br/api/pix/cashIn
  com Authorization: Bearer TOKEN, body { value: centavos }.
  Guardar o id retornado.
- Conferir: GET /api/transactions/{id}. ATENCAO: o id volta
  minusculo na criacao e MAIUSCULO na consulta — comparar
  sem diferenciar maiusculas.
- Quando status = paid: gerar a key do plano comprado,
  vincular ao comprador, marcar payment como paid (entrega
  automatica). Ha um verificador periodico no servidor + o
  botao "Ja fiz o pagamento" no site.
- Precos: Diario R$3,90 / Semanal R$8,90 / Mensal R$15,90 /
  Vitalicio R$22,90 (em centavos no banco).
